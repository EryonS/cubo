# Cubo Blocks: React Native port (design)

Date: 2026-10-04. Status: approved in brainstorm, milestone 1 next.

## Why
The game ships today as a Capacitor WebView (`www/`, canvas 2D + DOM screens). We rewrite it as a real
native app on iOS and Android with Expo, for three reasons:
- **Performance**: drag, animations and clears at native frame rate, the dragged shape glued to the finger.
- **Native feel**: real tab bar, stack transitions, bottom sheets, system haptics, back gesture.
- **Tooling**: TypeScript, components, the same stack as the sibling apps (Ressac, Caninome).

The web build is dropped for now. Nothing is in production or TestFlight: no save migration from the
Capacitor app, the `appId` `com.slapps.cubo` is kept.

## Scope and success
- **End state: feature parity** with the Capacitor game (Classique / Chrono / Chill, Aventure 20 levels a
  world with boss fights and chests, Mondes, Puzzles + Puzzle surprise, Défis / daily / streak, Boutique
  + bonus upgrades, Cubo + wardrobe, album / stickers / trophies, profile and stats, 7 season events,
  tutorial + tips, FR / EN, rewarded ads, cloud save, share).
- **Look**: the game keeps its art direction and drawings (`DESIGN.md`): board, cells, Cubo, hats, world
  and season themes, HUD, effects. Screens outside the game follow native conventions (tab bar, stacks,
  sheets) with the same palette, fonts and tone. No redesign.
- **Delivery in milestones**, each one playable on the iOS simulator and the Android emulator, and
  shippable to TestFlight. The owner tests and asks for fixes before the next milestone starts. Each
  milestone gets its own implementation plan, written right before it starts.
- No feature cuts. YAGNI applies to new things only.

## Stack (aligned on Ressac)
- Expo SDK 57, React Native 0.86, React 19, TypeScript, `app.config.ts`.
- Builds: `expo prebuild`, then Xcode directly (Archive, TestFlight). No EAS. `ios/` and `android/` are
  generated and committed, never edited by hand: config goes through `app.config.ts` and plugins.
- Navigation: React Navigation 7 (`bottom-tabs` + `native-stack`), `@gorhom/bottom-sheet` for sheets.
- Rendering: `@shopify/react-native-skia` for everything that is canvas today.
- Gestures and motion: `react-native-gesture-handler`, `react-native-reanimated` 4 + `react-native-worklets`.
- State: `zustand`. Storage: `react-native-mmkv`.
- Fonts: `expo-font` (Baloo 2, Press Start 2P), also loaded as Skia typefaces for canvas text.
- Native services: `expo-haptics`, `expo-localization`, `expo-status-bar`, `expo-splash-screen`,
  `react-native-audio-api` (WebAudio API, the sfx and music are synthesized), React Native `Share`,
  `react-native-google-mobile-ads` + `expo-tracking-transparency` (milestone 9).
- Cloud save: provider decided at milestone 9 (Firebase as the current code, or Supabase as the sibling
  apps). No Firebase project exists yet, so nothing is lost either way.
- Tests: `tsx --test` on pure modules (`npm run check:unit`), `tsc --noEmit`, ESLint.

## Repository layout
At milestone 1 the whole Capacitor game moves to `legacy/` with `git mv` (`www/`, `ios/`, `android/`,
`capacitor.config.json`, `resources/`, `tools/`, `tests/`, the Capacitor `package.json` scripts and
dependencies). It stays runnable as a reference (`npm run legacy` serves `legacy/www`) and is deleted at
milestone 10. The Expo app takes the repo root:

```
app.config.ts        identity (Cubo, com.slapps.cubo), fonts, plugins
index.ts, App.tsx    entry, providers (gesture root, safe area, navigation, fonts, splash)
ios/  android/       generated by prebuild, committed
src/
  core/              logic, meta, levels, worlds, puzzles, tutorial, sync, rng: pure TS + *.test.ts
  i18n/              tr, locale, en.ts, language setting
  game/              run controller: actions (place, bonus, undo, end), timers, drag model, boss, flow
  render/            Skia drawing: board, cells, hud, effects, theme backgrounds, frame clock
  mascot/            Cubo in Skia: body, hats, fx, lines
  screens/           one screen per file
  navigation/        RootNavigator, tabs, route types
  ui/                shared components (Button, Sheet, Wallet, Icon, Segmented, Toggle...)
  platform/          storage, haptics, audio, ads, cloud, share
  theme/             tokens from DESIGN.md, world and season palettes
assets/              fonts, icon, splash
scripts/             balance, bot, i18n key check
docs/                CLAUDE.md rewritten for the new layout, features/*.md updated per milestone
```

Rules carried over from `docs/CLAUDE.md`: `core/` stays pure (no React, no native module,
JSON-serializable state, seeded RNG); every player-facing string goes through `tr()` with its English in
`en.ts`; French source text is the key; no emoji anywhere, icons are drawn (Skia or SVG paths reused from
the current markup); a shape is a "forme", a "pièce" is a coin; saved shape changes need a migration in
`M.migrate` and a test.

## Core port
- UMD / CommonJS modules become ES modules in TypeScript. Logic is ported line for line, no behavior
  change. Types (`RunState`, `Profile`, `Settings`, `Shape`, `Level`, `World`...) describe what the
  functions already return; where a type is awkward, `core` keeps its shape and the type follows.
- The 15 `tests/*.test.js` files become `src/core/*.test.ts` and must keep passing: they are the proof
  that the port is faithful. `tools/bot.js`, `balance.js`, `i18n-keys.js` move to `scripts/` in TS.
- Dropped because nobody has an old save: the `gridlock.*` key move and `LEGACY_KEY`. `M.migrate` stays.

## App state
Two layers, kept apart so the game never re-renders React at frame rate:
1. **Persistent state**: run, profile, settings, in one zustand store. Every action calls a pure core
   function (`L.place`, `M.applyRun`...), replaces the state and saves to MMKV (`cuboblocks.v2`,
   `cuboblocks.profile.v1`, settings key). Screens subscribe with selectors.
2. **Animation state**: what `anim-state.js` holds today (pops, fades, particles, floaters, banners,
   shake, sweeps, punch, falls, shifts, drops, flyers, slot timings). A mutable module-level object read
   by the renderer, written by the game flow. Never in React state.

The frame clock (bonus timers, chrono, game end) runs from the game screen's frame loop, only while
the screen is focused and no sheet or pause is open, and the app is in the foreground.

## Rendering
- The game canvas is one Skia `<Canvas>` filling the game screen. Its static and animated content (theme
  background, board, cells, special cells, tray, HUD band, effects, banners, boss, Cubo) is drawn in
  **immediate mode**: each frame where something moves, the renderer records an `SkPicture` with Skia's
  imperative canvas API (`drawRRect`, `drawPath`, paints, gradients, text) and hands it to a `<Picture>`.
  This maps the ~900 `ctx.*` calls of the current code one by one, keeps the drawing code readable next
  to the original, and stops recording when nothing moves.
- Helpers replace canvas idioms: `withAlpha`, rounded rects, gradients, shadows (Skia blur mask
  filter / image filter), text with Skia typefaces and measured widths, save / restore, transforms.
- **The dragged shape is drawn in its own layer** on the UI thread: a `<Picture>` of the shape (recorded
  once at pick-up) inside a `<Group>` whose transform is a Reanimated derived value from the pan gesture.
  The shape follows the finger even if the JS thread is busy. Snap target, ghost preview and placement
  are computed on the JS side from the same position (throttled to a frame) and drawn by the main picture.
- Layout (`render/layout.js`) becomes a pure function of the screen size and safe-area insets, recomputed
  on size change, shared by the renderer and the gesture hit tests.
- Small canvases elsewhere (home hero art, Cubo on the home screen, shop previews, world map art, album
  stickers) are Skia components that reuse the same drawing functions.
- Reduced motion follows the system setting (`AccessibilityInfo` / Reanimated `useReducedMotion`).

## Screens and navigation
- Tab bar (native bottom tabs): **Jouer**, **Défis**, **Boutique**, **Profil**, as today.
- Stacks: Jouer → Game (full screen, tab bar hidden), Aventure map → world → level; Défis → daily,
  Puzzles; Profil → stats, album, settings, account.
- Sheets (`@gorhom/bottom-sheet`): free-game mode picker, missions, confirm dialogs (styled, as the
  current `#ask`), pause, level intro / result where they are overlays today, end of tutorial.
- Game over / result: full-screen modal in the stack, with Cubo's pose.
- Android back and iOS back swipe come from the navigators; the game screen asks before leaving a run
  the same way the current pause menu does.
- Wallet, line of the day, missions pips, event banners: shared `ui/` components.

## Platform services
- Haptics: same `HAPTICS` table, played with `expo-haptics` impacts (light / medium / heavy by pulse
  length, as `impactPattern` does now), gated by the Vibrations setting.
- Audio: `sfx.js` and `music.js` port onto `react-native-audio-api`'s `AudioContext`; same synthesis.
  Audio pauses with the app in the background.
- Share: React Native `Share` for the daily result text.
- Status bar and splash: `expo-status-bar`, `expo-splash-screen`, background `#ffeef4`.
- Ads (milestone 9): rewarded ads with test ids, ATT prompt before the first ad on iOS, consent form.
- Cloud save (milestone 9): `core/sync.ts` (merge rules) is ported in milestone 1 with its tests; the
  provider and sign-in come at milestone 9.

## Error handling
- Storage: a save that fails to parse is set aside under `<key>.broken` and the app starts fresh (as the
  web build does); `M.migrate` runs on every load.
- Native services (audio, haptics, ads, cloud) never block play: every call is wrapped and fails silent,
  with a `__DEV__` warning.
- A render error in the game canvas is caught by an error boundary on the game screen that offers to go
  back home, the run stays saved.

## Testing
- Pure modules: `npm run check:unit` (ported tests + new tests for new pure helpers, e.g. layout and
  hit tests). `npm run check:types`, `npm run lint`.
- Each milestone ends with a written check list run on the iOS simulator and the Android emulator,
  compared side by side with `npm run legacy` when visuals are ported.
- TestFlight build possible from milestone 2 on (prebuild, Xcode, Archive).

## Risks
- **Skia picture per frame** cost on older Android phones: the main picture is only re-recorded while
  something animates, the background is cached in its own picture, and the dragged shape is on the UI
  thread. Measured at milestone 2 on the Android emulator and a real device if available.
- **Canvas text** (score, floaters, banners) needs Skia typefaces loaded before the first frame: the
  splash stays up until fonts are in.
- **react-native-audio-api** maturity: if a synthesis feature is missing, fall back to pre-rendered
  short samples played with `expo-audio` for the affected sounds.
- **Library versions on SDK 57**: install through `npx expo install` so versions match the SDK.
