# Cubo Blocks: guide for Claude Code

Read this before adding or changing a feature. It routes you to the right feature file and module.

## React Native port in progress (since 2026-10-04)
The game is being rewritten as a native app with Expo (SDK 57, React Native, TypeScript), one milestone at a
time: [spec](superpowers/specs/2026-10-04-react-native-port-design.md), plans in `superpowers/plans/`. The web
build is dropped. Until the switch-over (milestone 10):
- **New code lives in `src/`** at the repo root (Expo app, `app.config.ts`, `ios/` + `android/` generated by
  `npm run prebuild`, committed, never edited by hand; release builds go through Xcode, no EAS).
- **The Capacitor game moved to `legacy/`** (`legacy/www`, `legacy/tests`, `legacy/tools`...). It is the
  reference for everything not ported yet: every path below that starts with `www/`, `tests/` or `tools/`
  now lives under `legacy/`. Run it with `npm run legacy` (http://localhost:8000) to compare.
- `src/core/` is a line-for-line TypeScript port of `legacy/www/src/core/`. `src/core/logic.parity.test.ts`
  replays games, levels and puzzles against the legacy modules: a rule change must go to both until
  `legacy/` is deleted, or that test fails.
- Rules that still hold in `src/`: `core/` pure (no React / native module), French text in `tr()` with its
  English in `src/i18n/en.ts` (`npm run i18n`), no emoji, "forme" / "pièce", a migration + test for any saved
  shape change. The language is set before any core module loads (`index.ts` → `bootLang()`): core tables
  call `tr()` at load, so a language change reloads the app.
- Checks: `npm run check:unit`, `npm run check:types`, `npm run lint`; visual changes on the iOS simulator and
  the Android emulator (`npm run ios` / `npm run android`).
- Game screen (milestone 2, done): `src/screens/GameScreen.tsx` draws the run with Skia. `src/render/draw.ts`
  ports the legacy canvas code call for call through `src/render/g.ts` (a canvas-2D-like wrapper over
  SkCanvas); the run picture is recorded on the JS thread only while something moves (`animating()` in
  `src/game/anim.ts`), the dragged shape is a separate picture moved on the UI thread. Geometry is pure and
  tested (`src/render/layout.ts`, `src/game/drag.ts`); moves go through `src/game/run.ts` (commit, end of run).
  Only Classique with the Jouet theme and the classic block skin so far.
- Juice (milestone 3, done): combo feel lives in `src/game/juice.ts` (pure: tiers, banners, pennant), drawn by
  `src/render/draw.ts`; effects state in `anim` (`animating()` = busy, `ambient()` = pennant / combo pulses
  redrawn at half rate). Haptics: `src/platform/haptic-pattern.ts` (pure) + `haptics.ts` (expo-haptics).
  Sound: `src/audio/sfx.ts` and `songs.ts` (pure scores) played by `engine.ts` on react-native-audio-api;
  `wireAudio()` in App.tsx suspends everything in the background.
- Boutique and game over (milestone 4): `src/screens/ShopScreen.tsx` (tabs Thèmes / Blocs / Cubo / Bonus; skin previews
  through `src/ui/DrawCanvas.tsx` + `render/preview.ts`; Cubo cards use the placeholder `render/cubo-preview.ts` until
  milestone 5; theme previews show board colors from `render/board-themes.ts`). Equipping a block skin applies in game
  at once (`themeFor`). Game over: `src/screens/GameOver.tsx`, summary tiles in `game/summary.ts`; the rewarded "double
  coins" button is the `DoubleCoinsAd` hook (milestone 9). `ask()` dialogs render in a native Modal, over bottom sheets.
- Not ported yet (milestones 4-9): bonus icons on blocks, inventory, undo, trash,
  other modes and themes, every screen beyond the 4 placeholder tabs, Cubo, ads, cloud save. The sections
  below still describe the legacy game.
- Simulator checks without hands: `idb ui tap/swipe` (fb-idb) drives the iOS simulator; points = pixels / 3.

## Name
- Name: **Cubo Blocks** (store and web), **Cubo** under the icon, appId `com.slapps.cubo`, domain `cuboblocks.app`, repo `EryonS/cubo`. Internal ids use `cuboblocks` / `CuboBlocks*` (save keys `cuboblocks.*`, globals `window.CuboBlocksMeta`...). Old name Gridlock: `gridlock.*` saves are moved to the new keys once at start-up (`platform/storage.js`, `i18n/setup.js` for the language); `gridlock.v1` stays the legacy format key.

## Layout
- `www/` is the whole game (web root, and Capacitor's `webDir`). `ios/` and `android/` are the native shells generated by Capacitor: edit their config there, never copy game files in by hand (`npm run sync` does it).
- `www/src/core/`: rules and progression (`logic`, `meta`, `worlds`, `levels`, `tutorial`, `puzzles`) and `i18n` (tr). Pure, tested in node.
- `www/src/i18n/`: `en.js` (English dictionary) and `setup.js` (picks the language, translates the static HTML); loaded right after `core/i18n.js`, before the other core modules.
- `www/src/` app files, one entity per file, loaded in order by `<script>` tags in `www/index.html`:
  `app/base.js` (shared names) → `ui/icons.js` → `themes/` → `platform/storage.js` → `game/anim-state.js` → `themes/current.js` → `render/layout.js` → `audio/` (sfx, music) → `platform/haptics.js` → `render/helpers.js` → `game/` (cells, boss, drag, flow) → `screens/` + `ui/` → `mascot/` → `render/` (loop, hud, board, effects) → `boot.js` (runs last).
- `www/vendor/`: third-party files served as is (Firebase compat SDK, `npm run vendor`), loaded on demand.
- `www/css/`: one stylesheet per area, linked in cascade order from `www/index.html`.

## Hard rules
- `www/src/core/*.js` stay **pure**: no DOM, no `window`, JSON-serializable state, seeded RNG only.
- App files are classic scripts sharing one global scope (no bundler, no imports): a top-level `const`/`let`/`function` is visible to every file. Names must stay unique across `www/src/`.
- Code that **runs at load** (top level, not inside a function or listener) can only call functions from its own file or earlier files, and only read `const`/`let` from earlier files. Put start-up work that needs everything in `boot.js`.
- New app file → add its `<script>` in `www/index.html` at the right place **and** to `ASSETS` in `www/sw.js`, bump `CACHE`. Same for any new static file (font, image, stylesheet).
- UI copy is written in **French** in the code and translated to English (FR + EN, device language by default, Réglages > Langue to change). A shape to place is a **forme** (EN "shape"), a **pièce** is always a coin. No emoji anywhere (UI, docs shown to players): draw icons on canvas or in SVG.
- Every player-facing string goes through `tr('…')` or `` tr`… ${x}` `` (core too), with its English in `www/src/i18n/en.js` (key = French text, `{}` per value, a function for plurals). Static text in `www/index.html` is translated at start-up as is. `npm run i18n` lists missing / unused keys; `tests/i18n.test.js` fails on any gap or on placeholders / markup that differ. Dates and numbers use `locale()`, never a hard-coded `'fr-FR'`. Plural choice that depends on the language: `CuboBlocksI18n.many(n)`.
- Any change to a saved shape (`cuboblocks.v2` run state, `cuboblocks.profile.v1` profile) needs a migration in `M.migrate` + a test in `tests/`.
- Visual work follows `DESIGN.md`; product scope follows `PRODUCT.md`.
- Run `npm test` before calling work done; check the UI in a browser for visual changes (`npm run serve`), and in the simulator for native-only changes (`npm run ios` / `npm run android`).
- Changing Aventure rules or piece odds: rerun `npm run balance` and retune `www/src/core/levels.js`.

## Adding a new feature
1. Create `docs/features/<feature>.md` (template below) and add a row to the table above.
2. Put rules in a pure module (`www/src/core/`), rendering in the matching app file (see the layout above).
3. Add tests for the pure part in `tests/<module>.test.js`.
4. Update the feature file when behavior or saved state changes.

```markdown
# <Feature>
Status: shipped | planned
## What it does
## Files
## Saved state
## Gotchas
```
