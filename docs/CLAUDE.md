# Cubo Blocks: guide for Claude Code

Read this before adding or changing a feature. It routes you to the right feature file and module.

## Name
- Name: **Cubo Blocks** (store), **Cubo** under the icon, appId `com.slapps.cuboblocks`, domain `cuboblocks.app`, repo `EryonS/cubo`. Internal ids use `cuboblocks` (save keys `cuboblocks.v2`, `cuboblocks.profile.v1`).

## Stack
Native app with Expo (SDK 57), React Native and TypeScript. iOS only for now (no Android work yet).
Rendering with `@shopify/react-native-skia`, gestures and animation with react-native-gesture-handler and
Reanimated, bottom sheets with `@gorhom/bottom-sheet`, state in zustand, storage in MMKV, sound on
react-native-audio-api, ads with react-native-google-mobile-ads, cloud save on Firebase.

`ios/` and `android/` are generated by `npm run prebuild` from `app.config.ts`: committed, never edited by
hand. Release builds go through Xcode (Product > Archive), no EAS.

The game was first a web app wrapped with Capacitor; it was ported screen by screen
([spec](superpowers/specs/2026-10-04-react-native-port-design.md)) and the web version deleted on 2026-10-06
(commit e86a443, read it with `git show e86a443^:legacy/www/src/...`). Code comments like "(legacy shop.js)"
name the web file a piece of code was ported from.

## Layout
- `index.ts` → `bootLang()` sets the language before any core module loads (core tables call `tr()` at load, so a language change reloads the app), then `App.tsx` (fonts, store, audio wiring, first-launch tutorial, banner hosts, navigation).
- `src/core/`: rules and progression, pure and tested in Node: `logic` (run rules), `meta` (profile, coins, missions, skins, stickers, events), `worlds`, `levels`, `puzzles`, `tutorial`, `sync` (cloud merge), `i18n` (`tr`, `locale`). Imported as `L, WD, LV, T, PZ, M, S` from `src/core`.
- `src/state/`: zustand store (`store.ts`), saves (`persist.ts`), Aventure progress helpers (`progress.ts`).
- `src/game/`: the run and its app-side logic: `run.ts` (start, moves, bonuses, end, stage runs), `anim.ts` (effects state), `drag.ts`, `juice.ts`, `falls.ts`, `hud.ts`, `modes.ts`, `daily.ts`, `events.ts`, `puzzle.ts`, `levelend.ts`, `album.ts`, `summary.ts`, `tips.ts`, `tutorial.ts`, `account.ts`. Pure parts are tested.
- `src/render/`: Skia drawing. `g.ts` is a canvas-2D-like wrapper over SkCanvas, `ctx2d.ts` a canvas-2D context over it; `draw.ts` (board, tray, HUD, effects), `layout.ts` (geometry, tested), `cells.ts` (special cells), `board-themes.ts` (theme colors, `themeFor`), `decor/` (theme backgrounds), `boss.ts`, `preview.ts`, `cubo-preview.ts`, `icons.ts`, `tutorial.ts`.
- `src/screens/`: one file per screen (tabs Jouer / Défis / Boutique / Profil, stack routes Game, Adventure, Puzzles, Album, Event, Settings), sub-parts in subfolders. Routes in `src/navigation/`.
- `src/ui/`: the UI kit (`Screen`, `ScreenHeader`, `Card`, `ListRow`, `Segmented`, `Counter`, `StatTile`, `Button`, `Sheet` + `SheetHeader`, `Text`, `Tap`, `Toggle`...) and shared sheets and widgets.
- `src/theme/`: tokens, fonts, `elevation.ts` (`raised()` soft shadows), `useColors()` (menu colors of the equipped theme, `menu-themes.ts`).
- `src/mascot/`: Cubo (looks, moods and taps, body, hats, effects, line of the day).
- `src/audio/`: `sfx.ts` and `songs.ts` (pure scores), `engine.ts` (playback).
- `src/platform/`: MMKV store (`kv.ts`), haptics, ads, cloud.
- `src/i18n/`: `en.ts` (English dictionary), `lang.ts`.
- `scripts/`: `i18n-keys.ts`, `balance.ts` + `bot.ts`. `assets/`: icon, splash, fonts.

## Game screen
`src/screens/GameScreen.tsx` draws the run with Skia in three pictures: the background (recorded once per
size), the animated decor (~25 fps, only for themes with `animate`) and the run, recorded on the JS thread only
while something moves (`animating()` in `game/anim.ts`; `ambient()` redraws pennant / combo pulses / Cubo
breathing at a lower rate). The dragged shape is a separate picture moved on the UI thread. Moves go through
`game/run.ts` (commit, end of run, handlers for the game over, level end and puzzle end cards). The theme of a
run: `playedTheme` / `themeFor` in `render/board-themes.ts` (a level's or Mondes world, else the free run's own
theme, else the equipped one).

## Hard rules
- `src/core/` stays **pure**: no React, no native module, JSON-serializable state, seeded RNG only.
- UI copy is written in **French** in the code and translated to English (device language by default, Paramètres > Langue to change). A shape to place is a **forme** (EN "shape"), a **pièce** is always a coin. No emoji anywhere: draw icons with Skia or SVG paths (`ui/Icon.tsx`).
- Every player-facing string goes through `tr('…')` or `` tr`… ${x}` `` (core too), with its English in `src/i18n/en.ts` (key = French text). `npm run i18n` lists missing / unused keys. Dates and numbers use `locale()`, never a hard-coded `'fr-FR'`.
- Any change to a saved shape (`cuboblocks.v2` run state, `cuboblocks.profile.v1` profile) needs a migration in `M.migrate` (or a default in `loadSaved`) + a test.
- Menus go through the UI kit and tokens: soft shadows with `raised()`, no thick bottom borders. Check every theme (light, dark, Rétro). Visual work follows `DESIGN.md`; product scope follows `PRODUCT.md`.
- Before calling work done: `npm run check:unit`, `npm run check:types`, `npm run lint`; visual changes on the iOS simulator (`npm run ios`).
- Changing Aventure rules or piece odds: rerun `npm run balance` and retune `src/core/levels.ts`.
- Simulator checks without hands: `idb ui tap/swipe` (fb-idb) drives the iOS simulator; points = pixels / 3.

## Adding a new feature
1. Create `docs/features/<feature>.md` (template below) and add a row to the table above.
2. Put rules in a pure module (`src/core/` or a pure file in `src/game/`), screens in `src/screens/`, shared UI in `src/ui/`.
3. Add tests for the pure part next to it (`<module>.test.ts`, run by `npm run check:unit`).
4. Update the feature file when behavior or saved state changes.

```markdown
# <Feature>
Status: shipped | planned
## What it does
## Files
## Saved state
## Gotchas
```
